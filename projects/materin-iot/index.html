概览

Materin IoT 是一套物模型驱动的通用 IoT 平台：设备通过产品/物模型描述能力，平台负责接入、指令、时序存储、规则与开放 API。当前为第一版，覆盖私有化部署所需的最小完整链路。

它与系列其他项目共用同一套 UI 规范与命名契约：颜色跟随用户主题，形状与间距固定，改一个令牌全体生效。

平台能力

能力说明
RBAC 与认证用户/角色/菜单/部门；JWT 登录态外置 Redis（可吊销、轮换、失败限流）；权限码控制
产品管理productKey 自动生成；品类/协议/发布状态；设备接入计数
物模型属性/方法/事件三要素 JSON 存储；版本与发布状态管理
设备管理设备密钥一机一密；批量导入；在线状态（滑动 TTL）；最近在线
MQTT 接入EMQX 双实例：内部（设备 secret + per-device topic ACL）+ 开发者（AK/SK，open/ 命名空间），规则 + Sink 消息互通
指令下发requestId + Redis 信箱跨实例回传；同步等待设备应答（超时 504）；大报文引用传递
时序存储Apache IoTDB 2.0（standalone）
开发者中心应用（AK/SK）管理；swagger 接口清单同步；接口勾选授权；接入指引
API 文档knife4j（/doc.html）；OpenAPI v3 全量接口/参数/出入参/权限说明

MQTT Topic 规范

统一前缀 materin/{productKey}/{deviceKey}/：

Topic方向用途
.../report设备→平台数据上报
.../event设备→平台事件/告警上报
.../reply设备→平台指令响应（回带 requestId）
.../cmd平台→设备指令下发

完整设计（鉴权链路 / ACL / 共享订阅 / 容量治理）见 backend/docs/mqtt-design.md。

materin-iot/
├── backend/                       # 纯 Spring Boot 模块化单体（Java 21，无 Spring Cloud）
│   ├── server/                    # 启动入口：装配全部模块，API 统一前缀 /api/v1
│   ├── common/                    # 共享内核：R/异常/分页、Redis keys、跨模块 SPI、Topic 常量
│   ├── system/                    # 系统板块
│   │   ├── system-rbac/           #   用户/角色/菜单/部门 + JWT 认证
│   │   └── system-openapi/        #   开发者中心：应用(AK/SK)、接口清单、接口授权
│   └── component/                 # 功能组件板块
│       ├── device-component/      #   设备/告警/规则/命令下发
│       ├── product-component/     #   产品/物模型
│       └── network-component/      #   MQTT 接入 + EMQX 配置
├── frontend/                      # 前端（TypeScript）
├── deploy/                        # 部署编排（docker-compose / 初始化脚本）
└── docs/                          # 文档

Overview

Materin IoT is an open IoT platform driven by thing-models: devices describe their capabilities through products and thing-models, while the platform handles onboarding, command dispatch, time-series storage, rules and the open API surface. This is the first release, covering the minimum complete path needed for private deployment.

It shares one UI spec and naming contract with the rest of the series: colours follow the user's theme, shape and spacing are fixed, one file changes all of them.

Platform capabilities

CapabilityNotes
RBAC & authUsers / roles / menus / departments; JWT in Redis (revocable, rotatable, fail-rate-limited); permission-code control
ProductsAuto-generated productKey; category / protocol / release status; device count
Thing-modelProperties / services / events as JSON with version and release state
DevicesOne secret per device; batch import; online status (sliding TTL); last-seen
MQTT onboardingTwo EMQX instances: internal (device secret + per-device topic ACL) and developer (AK/SK, open/ namespace); rule + Sink interconnects them
Command dispatchrequestId + Redis mailbox across instances; synchronous wait for device reply (504 on timeout); reference passing for large payloads
Time-series storageApache IoTDB 2.0 (standalone)
Developer portalApps (AK/SK); swagger spec sync; per-API authorization; onboarding guide
API docsknife4j (/doc.html); full OpenAPI v3 spec with params, payloads and permissions

MQTT topic convention

Uniform prefix materin/{productKey}/{deviceKey}/:

TopicDirectionPurpose
.../reportdevice → platformdata reporting
.../eventdevice → platformevents / alerts
.../replydevice → platformcommand reply (carries requestId)
.../cmdplatform → devicecommand dispatch

Full design (auth chain / ACL / shared subscriptions / capacity governance) lives in backend/docs/mqtt-design.md.

Repository layout

materin-iot/
├── backend/                       # Pure Spring Boot modular monolith (Java 21, no Spring Cloud)
│   ├── server/                    # Boot entry; assembles all modules; unified /api/v1 prefix
│   ├── common/                    # Shared kernel: R / exception / paging, Redis keys, cross-module SPI, topic constants
│   ├── system/                    # System layer
│   │   ├── system-rbac/           #   users / roles / menus / departments + JWT auth
│   │   └── system-openapi/        #   developer portal: apps (AK/SK), spec sync, per-API auth
│   └── component/                 # Feature components
│       ├── device-component/      #   devices / alerts / rules / command dispatch
│       ├── product-component/     #   products / thing-models
│       └── network-component/      #   MQTT onboarding + EMQX configuration
├── frontend/                      # Frontend (TypeScript)
├── deploy/                        # Deployment orchestration (docker-compose / init scripts)
└── docs/                          # Documentation
